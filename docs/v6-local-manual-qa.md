# V6 本地手工验收清单

本清单只在生产或预发服务器上使用**真实材料**做人工验收。

禁止把真实简历、社保、OCR 原文、姓名或公司原名写入本仓库、测试 fixture、升级包或工单附件。

## 环境

- 使用更新包 `resume-social-security-check-update-<shortSha>.tar.gz`
- 先校验 `.sha256`
- 只重建 `resume-social-security-check-app`
- 不要改 Caddy、OrangeITO、Docker Volume、生产 `.env`
- 本轮自动化不连接生产；此清单由现场人员执行

## 材料准备

- [ ] 至少 1 份带原生文字层的 PDF 简历
- [ ] 至少 1 份扫描件/图片简历
- [ ] 至少 1 份 DOCX 简历（如有）
- [ ] 至少 1 份社保 PDF（含单位编号与公司名分列）
- [ ] 材料只放在服务器本地，不回传到仓库

## 识别链路

- [ ] 文字层正确、OCR 较差时，结果采用原生文字，仍能打开识别依据看到 OCR 原文
- [ ] 扫描件无文字层时，结果采用 General OCR
- [ ] 两边一致时标记为一致，不出现来源冲突
- [ ] 公司名两边不同时出现「来源冲突，待确认」，不能自动通过
- [ ] 月份两边不同时出现「来源冲突，待确认」，不能自动通过
- [ ] 某一页 OCR 失败时，其他页结果仍在
- [ ] 多页经历不会被拼成一个公司名
- [ ] 重复页只识别一次，月份不双计
- [ ] 社保只有 Table OCR 时任务继续
- [ ] 社保只有 General OCR 时任务继续
- [ ] 两边都失败时任务继续，字段待确认
- [ ] 单位编号与公司名分区域时仍能映射
- [ ] 编号映射不唯一时待确认
- [ ] 「深圳市示例…有限公司」中的「深圳市」不被删除
- [ ] 独立「深圳市：」前缀被清理
- [ ] 映射失败显示缴费类型待确认，不是个人缴费
- [ ] 同月公司+个人只计 1 个总月数，并显示重叠月份
- [ ] 人工修正后立即重新配对、重算、更新复制文本
- [ ] 撤销后恢复系统识别值
- [ ] 结论页、工作台、历史记录、一键复制的整体结论一致
- [ ] 旧 schema 2/4/5 记录只读展示，不被重算
- [ ] 手机为三块卡片；桌面为高对比度对照表
- [ ] 日志没有简历原文、OCR 全文、姓名、公司原名或密钥

## 界面

- [ ] 每个关键字段可展开「识别依据」
- [ ] 依据中有来源、页码、短原文，主表没有大段 OCR
- [ ] 日期和「X年Y个月」不换行
- [ ] 公司名字号不小于 14px

## 部署（仅服务器本机）

- [ ] `deploy-update.sh` dry-run 通过
- [ ] `--apply-local` 必须显式确认，不会被误当成已部署成功
- [ ] 构建标签为 `resume-social-security-check:v6-<shortSha>`
- [ ] `docker image inspect` 能看到新镜像
- [ ] 健康检查包含容器 healthy、镜像 ID、站点 HTTP 200、SQLite ok
